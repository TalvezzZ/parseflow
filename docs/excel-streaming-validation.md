# Excel streaming extraction validation

Validated locally on 2026-11-09. Numeric fixtures generated by `scripts/benchmark_excel.py`, 100 columns per row, up to 30,000 rows per worksheet; ten-million-cell fixture has four worksheets. Parser uses defaults including 10 million retained cells and 4 GiB SQLite/image disk budget.

| Retained cells | Source bytes | SQLite bytes | Worker peak RSS | Worker time | Serialized provider preview |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1,000,000 | 2,737,402 | 129,855,488 | 58,556,416 bytes (55.8 MiB) | 15.130 s | 126,073 bytes |
| 10,000,000 | 27,442,471 | 1,317,302,272 | 58,015,744 bytes (55.3 MiB) | 154.513 s | 129,007 bytes |

Both completed with `success`, exact retained-cell counts, source truncation=0, and preview truncation=1. RSS is the parser subprocess high-water mark (`resource.getrusage`), not combined web/API process memory. Times exclude fixture creation, API result handling and optional CSV exports. This demonstrates bounded reading/preview memory for this numeric workload, not a universal latency/RSS guarantee for arbitrary workbooks. Formula-heavy, shared-string-heavy, metadata-heavy, and image-heavy documents differ; independent archive, XML-record, row/column and disk budgets remain enforced.

## Data contract

- Complete retained cells are stored once in `workbook.sqlite`: `sheets(sheet_id,metadata)` and `cells(sheet_id,row,column,payload)`.
- Task JSON holds bounded table previews and metadata summaries. It does not hold all cells. Consumers requiring complete data must use the row API or database artifact.
- `GET /api/v1/tasks/{task_id}/sheets/{sheet_id}/rows?after_row=0&limit=100` uses keyset pagination over nonempty original rows. Sheet IDs start at zero; row/column numbers start at one. Use `next_after_row`, not a fixed row increment. Oversized single rows return 413; data remains downloadable.
- Preview truncation does not make the task partial. Actual omissions caused by cell, row, column, sheet or metadata budgets produce partial status with reasons.
- Standard parsing excludes hidden and very-hidden sheets. Auxiliary shared-string/style/formula/metadata tables use SQLite secure deletion and are dropped before publication.
- Formula expressions and available cached results are retained; no recalculation or macro execution occurs. Phonetic runs are excluded from textual values.
- SQLite/image output is atomically staged by the parser subprocess. Parser and Excel export subprocesses are killed and reaped on coroutine cancellation; user-cancel markers are checked at short intervals. Cancelled outputs are reclaimed before final task state publication.
- Optional CSV exports use incremental escaped field writes, preserve sparse positions, and apply spreadsheet formula-injection escaping. Optional aggregate export limits do not remove the complete SQLite artifact.

## Validation coverage

Backend regression includes fixtures for dates, booleans, formulas, shared formulas, relationship-based sheet reordering, shared strings, phonetic annotations, metadata-only comments/hyperlinks, hidden-data erasure, sparse/style-polluted sheets, preview/source truncation separation, storage budgets, cursor pagination, API parameter bounds, upload-to-CSV integration, process cancellation and late task cancellation cleanup. XML adversarial tests cover long character data, attributes, nesting, record node limits, comments, UTF-16 and forbidden DTDs.

Frontend checks: 23 unit tests, production build, and Chromium checks using mocked pagination APIs at 1440px desktop / 390px mobile. A 30-sheet fixture issues one request for the selected sheet. Original row numbers and column gaps remain visible, stale requests abort, short cursor pages navigate correctly, and mobile has no page-level horizontal overflow. This was a built-asset browser smoke test, not a live production deployment verification.

## Reproduce

```bash
PYTHONPATH=. .venv/bin/python scripts/benchmark_excel.py --cells 1000000 10000000
.venv/bin/python -m pytest -q
```

Fixtures and full benchmark databases are temporary and are removed after the command finishes. Large databases are not committed to the repository.
