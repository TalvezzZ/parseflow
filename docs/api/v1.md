# ParseFlow REST API v1

## Stability guarantee

All public business endpoints are under `/api/v1`. v1 clients must tolerate newly added optional fields; ParseFlow will not remove an endpoint, required response field, stable status, error code, or opaque ID meaning during v1.x.

Forbidden public fields: `path`, `output_dir`, `callback`, `source_path`, `target_path`, `artifact_path`.

## Task workflow

1. `POST /api/v1/tasks/parse` as multipart with `file`, optional `goal`, optional `data_id`.
2. Poll `GET /api/v1/tasks/{task_id}`.
3. List/download outputs through `/api/v1/tasks/{task_id}/artifacts` and `{artifact_id}`.

Task statuses are `queued`, `planning`, `running`, `cancelling`, `succeeded`, `partial`, `failed`, `cancelled`, and `interrupted`. Retrying a terminal task creates a new task and retains `retry_of`.

## History and control

- `GET /api/v1/tasks?status=&query=&cursor=&limit=&sort=`
- `POST /api/v1/tasks/{task_id}/cancel`
- `POST /api/v1/tasks/{task_id}/retry`
- `DELETE /api/v1/tasks/{task_id}` for terminal tasks only.

All IDs are opaque: `file_`, `task_`, and `artifact_` followed by 32 lower-case hexadecimal characters.

## Result quality and exports

A terminal task result may contain additive `quality` and `provenance` objects. They report input classification, document counts, OCR/truncation semantics, reliable confidence when available, parser metadata, and the attempted Provider chain. Unknown confidence is JSON `null` rather than an inferred value.

Successful document results may include `export` artifacts for JSON, Markdown, plain text, CSV, XLSX, and table JSON/Markdown. Download these only through the artifact URL; filesystem storage keys are not part of the public contract.

## Error compatibility

Errors retain machine-readable `detail.code` values and HTTP status semantics. Clients should use codes rather than localized messages.
