# ParseFlow v1.6.0 技术方案：统一文件结果存储与 Excel 完整坐标支持

状态：本地实现及验证完成（2026-11-15）。版本选择：原运行版本为1.4.0，1.5.0已有运行可靠性方案，因此本次独立架构改造使用1.6.0；未创建远端Release、Tag或推送。

本地验证：后端305 passed、1 skipped；前端39 passed、生产构建通过；OpenAPI/版本元数据契约已同步。千万级数值Excel精确完成，约135秒、解析进程峰值约56MiB、压缩文件约50MiB。详细条件与边界见 [验证记录](file-result-storage-validation-1.6.0.md)。

## 目标与边界

完整解析结果以文件作为唯一权威来源；任务元数据仅保留状态、统计、稳定结果引用和有界预览。首先降低持久化记录、任务查询、重复序列化对可用性的影响。统一规则覆盖Excel、PDF、Word、PPT、图片、文本及音视频预处理结果。文件存储并不自动使第三方解析器内部成为流式，仍需明确各解析器的内存边界。

当前任务元数据已用JSON文件持久化，暂不为路径登记额外引入数据库；采用可迁移到数据库的相对storage_key契约。原有任务继续兼容读取，不自动大批迁移或删除旧结果。旧Excel SQLite结果继续读取。

## 统一布局与结果契约

每个任务仍使用既有受控artifact workspace，新增result/目录。result/manifest.json声明schema_version、文档类型、单元目录、数据块相对路径、范围、大小、SHA256和结果表示引用。完整document.json与独立表示文件保留原始结构化内容；按页面、幻灯片、内容块或数据表分块，避免任务记录携带完整内容。无页面定义的Word按内容块拆分；音视频目前仅保存已有预处理结果，不虚构ASR。

TaskResultEnvelope新增result_ref（相对键/版本/访问URL），document字段仅为有界预览并显式标记preview_truncated；原API读取旧任务内嵌document继续可用。完整数据通过受鉴权下载/结果单元分页接口获取。任务列表不自动读取完整结果。禁止对外泄露绝对路径。

## Excel

按Sheet独立目录、按行块追加写入压缩JSONL（标准库gzip，避免引入额外运行时依赖），块目录支持原始行号游标定位。行、列维持1-based，sheet_id维持0-based。辅助共享字符串、样式、公式查找可使用私有临时SQLite，但最终完整结果不依赖单元格数据库，辅助文件不发布。每块设置记录数和字节预算，单个巨行可跨块；查询必须返回完整行或显式413，不静默漏格。

XLSX/XLSM默认坐标上限提升至1,048,576行、16,384列；不展开空白矩形。有效单元格总数暂保留10,000,000，原文件/解压/XML/磁盘/耗时预算独立生效。预览额外限制行列展开，避免支持XFD列后预览膨胀。稀疏导出有单独预算。跨Sheet公式保留引用，不计算。

## 生命周期与可用性

结果先写私有临时目录，完成数据块及manifest后原子发布，最后发布任务引用。取消、超时、失败不得将半成品暴露为成功结果。任务删除/TTL回收沿用任务artifact根目录清理；新增结果同属该目录。路径解析拒绝越界、符号链接及未知任意路径。按需读取仅解压相关块；文件数和元数据也设预算。

## 执行顺序

1. 落地方案和版本约定。
2. 实现统一结果文件仓库、有界预览、manifest/单元访问、旧任务兼容。
3. 改造Excel写入器/读取器/导出器，保留旧SQLite读取，放开坐标并限制预览展开。
4. 所有解析结果统一发布，前端明确预览和完整结果入口，保留已有分页能力。
5. 同步版本、OpenAPI、配置、操作与迁移说明。
6. 回归、文件类型契约、分页/稀疏坐标、取消/清理、规模与内存验证。

## 验收

- 新任务记录大小受预览预算约束，不能随完整正文/单元格数量线性增长；完整数据可按引用下载/分段读取。
- 所有现有受支持文件类型均进入统一文件发布流程，内容不因预览缩减丢失。
- Excel按Sheet分块，A1048576/XFD1/XFD1048576的少量数据可读取；不因空白坐标展开造成巨大内存或输出。
- 新文件存储与旧内嵌/SQLite任务可同时读取。
- 元数据引用与文件内容一致，路径与校验正确；取消、删除、TTL和重启覆盖新增文件。
- 后端测试、前端单测/构建、契约快照通过；性能只报告实测范围，未执行的部署检查明确记录。
